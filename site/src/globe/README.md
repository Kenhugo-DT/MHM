# Isolated globe view

`globe.html` is a separate Vite entry point. It does not import the 2D map,
its layout code, or its state. The existing map only links to this page.
The entry point displays a client-side preview password gate before importing
the globe or fetching its data. It uses session storage for the current tab.
Because GitHub Pages is static, this is only a casual viewing barrier: the
password and published assets are not secret or server-protected.

The globe reads the published graph JSON and, when configured, the public
Supabase `entities` and `relations` tables. It makes no writes. It loads
approved facts for the selected node. `geography.mjs` owns its own place
catalogue and placement rules. Every placed node must retain a source URL;
nodes without a supported location remain searchable and are not assigned
invented coordinates.

The source-backed atlas is generated by `brain/scripts/scout-geography.mjs` into
`site/public/data/geography.json`, which this page loads separately from the
published graph. The scout checks published and (with `--live`) live band and
person nodes against their Wikidata/Wikipedia/MusicBrainz identities. It accepts
Wikidata formation places for bands and birthplaces for people only when the
place has a coordinate. Exact-title matches require a matching entity type,
musical occupation for people, and a unique graph label. Conflicting identities
are withheld; unapproved research candidates are written to a separate local
review report and never placed on the public globe.

To refresh the atlas after reviewing sources, run
`node --env-file=.env brain/scripts/scout-geography.mjs --live --candidates --audit-labels --accept-exact-labels --apply`
then `npm run brain:learn`. The geography JSON records the claim URL, coordinate
URL, identity-check URL where needed, and a short note explaining the meaning
and limits of each place. The learning model also gets context notes for existing
cross-place graph connections, not new inferred relationships. Nothing in this
workflow writes to Supabase or auto-approves a candidate.
The ignored local `brain/data/runs/geography-unresolved-review.json` records why
each remaining band/person could not be placed, so later source checks have a
specific queue instead of a silent gap.

Geography remains incomplete. Some source locations are cities, others are
regions or named buildings; marker precision varies and is not a verified
performance venue. A birthplace is not automatically an artist's musical base;
unknown locations remain unplaced and searchable. The year control highlights
documented start years only. It must not be labelled as activity, releases or
chart presence.

Future event layers should be separate, sourced records with their own entity
identity, place role, date precision and review status:

- release: artist / recording / release-group identity and release date;
- chart appearance: release, chart, country, dated rank and licensed source;
- concert: artist, event date, venue or city precision and evidence;
- studio: place identity plus a documented `recorded at` relationship;
- video: reviewed match to a specific concert, with a playable source link.

These layers can be rendered on this page without changing any 2D layout.
